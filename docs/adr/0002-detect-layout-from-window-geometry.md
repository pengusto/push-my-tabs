# Distinguish native layout, geometry estimates, and user confirmations

Read Firefox 142+’s public `browserSettings.verticalTabs` setting when available. Otherwise infer the tab layout from window and active-tab dimensions only when a command runs or the popup opens. Manual horizontal and vertical modes override automatic detection. Chrome’s public tabs/windows API has no documented orientation field; geometry keeps this local and idle without polling, while an open side panel may require confirmation.

The popup identifies the source as **Natively detected** for a native boolean, **Automatically estimated** for geometry, or **Manually set** for an explicit mode or a remembered site/path/geometry confirmation. Unavailable dimensions show a confirmation request rather than an invented result. A failed native read also requires confirmation.

Confirmations default to a global geometry hint so switching sites does not require repeated confirmation. Explicit exact-path and origin profiles retain precedence and are not promoted globally. Saving a global hint updates matching current-origin/current-path entries at that exact geometry in the same awaited storage write; otherwise an older exception could silently override the new confirmation. Exceptions for other sites and other measurements remain unchanged.

After exact site/path and exact global matches, allow a global hint within a Manhattan distance of 20px across the two rounded gaps: one rounding step in one dimension only. All nearby matches must agree. Conflicts require confirmation; approximate matches never create new saved keys, preventing gradual drift. A nearby hint that contradicts a clear heuristic estimate also requires confirmation rather than masking a possible orientation change. A 10px band on each side of the heuristic's 40px side-gap and 100px top-gap thresholds requires confirmation instead of flipping commands for a few pixels. Exact user confirmations and Firefox's native setting remain authoritative. Unknown larger geometry changes still require confirmation when ambiguous; no idle polling, new permissions or sticky last-layout cache is added.

Regression lesson: Chrome's tab width/height come from the WebContents container bounds, not the website's CSS content width. Ordinary content differences are not evidence of different browser geometry, and page zoom must not be assumed to change these API values without measurement. Browser UI (including side panels, DevTools and split views) can change the container. [Chromium's tab object implementation](https://chromium.googlesource.com/chromium/src/+/HEAD/chrome/browser/extensions/extension_tab_util.cc) is the owning source. `tests/api.test.mjs` and `tests/background.test.mjs` cover cross-site reuse, small variation, conflicts, threshold boundaries, no chained learning and switching to another confirmed layout. The browser UI regression also checks the shared default, awaited save/retry, legacy exception correction and explicit path scope using mock APIs.

Zen needs separate handling. Its `runtime.getBrowserInfo()` retains the Firefox name but adds a `zen` object. Zen’s own tab bar does not use Firefox’s `sidebar.verticalTabs` preference, which Zen 1.23.4b locks to false. Do not interpret its inherited Firefox API as the visible tab orientation. Detect the Zen marker, bypass that setting, and require a first geometry confirmation; saved confirmations remain reusable. This does not add a native Zen detection claim or new permissions.

Sources: [Firefox API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/browserSettings/verticalTabs), [Zen browser identity](https://github.com/zen-browser/desktop/blob/1.23.4b/src/toolkit/components/extensions/parent/ext-runtime-js.patch), [Zen preferences](https://github.com/zen-browser/desktop/blob/1.23.4b/prefs/firefox/browser.yaml), [Chrome tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs), [Chrome windows](https://developer.chrome.com/docs/extensions/reference/api/windows).

Regression lesson: the presence of an inherited API does not establish that a browser fork uses its underlying setting. `tests/firefox.test.mjs` checks stock Firefox, Zen’s identity and setting mismatch, and native-read failures; `tests/ui-flow.test.mjs` checks the source labels.
